# 官方 SDK 迁移（替换自研适配器层）

## Summary
删除 `model_adapters/`（手写请求拼装、响应解析、SSE 流解析）与 `embedding_adapters/`，新建 `model_clients/` 包：每家一个薄客户端类，内部全部调用官方 SDK（openai / anthropic / google-genai），对上层保持现有 parsed dict 契约（text / tool_calls / usage / finish_reason / raw_response），token 记账、事件日志、transcript hygiene 全部无感。顺带获得 SDK 内置的 429/5xx 自动重试。

## 一、新增 model_clients 包（核心）

新建 `Agent_Server/src/application/model_clients/`：

- `base.py`：
  - `ProviderClient` 协议：`async invoke(config, api_key, request) -> dict`、`async stream(config, api_key, request, on_text_delta) -> dict`；返回 dict 保持现有 parsed 结构（`text/tool_calls/finish_reason/stop_reason/usage/response_id/raw_response`）。
  - `ProviderClientError(status_code, message, response_body)`：统一包装三家 SDK 的 API 异常（`openai.APIStatusError` / `anthropic.APIStatusError` / `google.genai.errors.APIError`），供上层做 http_error 归类与 Gemini 400 去 tools 重试。
  - 从旧 base.py 迁移保留：`build_tool_name_map` / `remap_tool_calls` / `parse_tool_arguments` / 工具名 sanitize（Gemini 必需，属数据映射非协议拼装）。
- `openai_client.py`：`AsyncOpenAI(api_key, base_url=config.api_base_url, default_headers=config.extra_headers, timeout, max_retries=2)` → `chat.completions.create(...)`；流式 `stream=True, stream_options={"include_usage": True}`，文本增量经 `on_text_delta` 回调；messages/tools 从 `ModelInvocationRequest`（含 structured_messages 多模态 parts）映射，逻辑取自旧 `openai_chat.py` 的 `_build_messages` 但产出 SDK 参数。
- `anthropic_client.py`：`AsyncAnthropic(api_key, base_url, default_headers)` → `messages.create(system=..., max_tokens=config.max_output_tokens, tools=...)`；流式用 `messages.create(stream=True)` 事件流，usage 取 `message_start` + `message_delta`。
- `google_client.py`：`genai.Client(api_key, http_options=HttpOptions(base_url=规整后根地址, headers=..., timeout=毫秒))` → `client.aio.models.generate_content / generate_content_stream`；tools 转 `function_declarations`（沿用工具名 sanitize/remap）；usage 取 `usage_metadata`；base_url 需剥掉尾部 `/v1beta`（SDK 自行拼版本路径）；oauth2 时把 Bearer token 放入 `http_options.headers["Authorization"]`。
- `registry.py`：`resolve_client(config)` 按 `config.transport` 三选一（沿用现有 transport 枚举，OpenAI 兼容厂商继续走 openai_client）。
- 将 `model_adapters/provider_profiles.py` 原样移入 `model_clients/provider_profiles.py`（provider 归一化/能力推断与 HTTP 无关，`model_config_store.py` 等依赖它），更新全部 import。

删除文件：`model_adapters/` 下 `base.py`、`openai_chat.py`、`anthropic_messages.py`、`google_gemini.py`、`registry.py`、`__init__.py`（整个包移除）。

## 二、ModelRuntimeService 重写调用路径

`Agent_Server/src/application/models/model_runtime_service.py`：
- 删除 httpx / AdapterRegistry / ModelCompatibilityLayer 依赖；构造函数去掉 `adapter_registry` 参数。
- `_invoke_with_adapter/_send_with_adapter/_stream_with_adapter` 合并为：`resolve_client(config)` → 有 stream handler 时调 `client.stream(..., on_text_delta=self._emit_stream_chunk)`，否则 `client.invoke(...)`。
- 保留不变：OAuth/api_key 解析、`_sanitize_request_for_provider`、Gemini 400 去 tools 重试（改为捕获 `ProviderClientError.status_code == 400`）、`_http_error_result`（入参改为 ProviderClientError，response_mode 仍为 `http_error`）、usage 进 `response_summary["usage"]`（token 记账不动）。
- `response_summary` 里的 `provider_profile/transport` 字段改由 `resolve_provider_profile(config)` 提供。

## 三、连接测试与兼容门面清理

- 删除 `application/models/model_compatibility.py`（ModelCompatibilityLayer）。
- `application/settings/settings_service.py`：连接测试改为 `resolve_client(record)` + `await client.invoke(ping 请求)`，计时与错误消息逻辑保留，捕获 `ProviderClientError`；去掉 build_url/build_headers/build_request + httpx.Client 手工路径。
- `main.py`：移除 `build_default_adapter_registry()`、`app.state.model_adapter_registry`（实现时检查该 state 的其他消费者并同步清理），SettingsService/ModelRuntimeService 构造参数同步更新。

## 四、Embedding 链路迁移

- 删除 `application/embedding_adapters/` 整包。
- `model_clients/` 新增 `embeddings.py`：
  - OpenAI 兼容：`AsyncOpenAI(...).embeddings.create(model, input, encoding_format="float")`，向量按 index 排序返回。
  - Google：`genai.Client(...).aio.models.embed_content(model="models/<id>", contents=texts)`，取 `embeddings[i].values`；base_url 同样剥 `/v1beta`。
  - Anthropic：抛同文案 ValueError（无 embeddings API）。
  - `resolve_embedding_client(config)` 按 provider 分发（沿用现 registry 规则）。
- `application/context/embedding_runtime_service.py`：`build_request + httpx.post + parse_response` 三步替换为 embedding client 调用；缓存、维度归一化、`get_for_application("embedding_retrieval")` 路由逻辑全部不动；`adapter.key` 字段改为 client 标识字符串（保持 EmbeddingBatchResult 结构）。

## 五、依赖与配置

- `Agent_Server/pyproject.toml` dependencies 追加：`openai>=1.60.0`、`anthropic>=0.40.0`、`google-genai>=1.0.0`；当前环境三者均未安装，实施时 `pip install`。
- `httpx` 保留（OAuth token service、性能探针等仍在用）。
- 超时沿用 `LLM_REQUEST_TIMEOUT_SECONDS`（三家 SDK 均传 timeout）；重试用 SDK 默认 `max_retries=2`。

## Assumptions

- parsed dict 内的 `usage` 保持各家原始字段名（openai: prompt_tokens…；anthropic: input_tokens…；gemini: promptTokenCount…），`token_usage.normalize_usage` 已兼容三种，不需改动。
- SDK 流式取消/中断沿用现有行为（turn 级 interrupt 在图层处理，不在 HTTP 层）。
- `provider_profiles.py` 只迁移位置不改内容。
- MySQL 中存量 base_url 格式（store 已在 `_row_to_record` 里剥掉 `/chat/completions`、`/v1/messages`、`:generateContent`）与 SDK base_url 约定兼容；Google 的 `/v1beta` 剥离在 google client 内处理。
